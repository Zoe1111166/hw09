## 1. 程式用途與執行方式
本專案協助自動化清理兩場活動（桌遊體驗、電影欣賞）的原始文字報名名單。它能自動排除多餘空白、忽略大小寫不一致的輸入、對單一場次重複報名進行去重、並計算多種集合指標（共同參加者、只參加單場者、全部不重複參加者、通知預覽名單）。最後，依據各自去重後的名單長度，結合字典儲存的單價計算出各自的費用與總應收費用，輸出格式化的摘要。

## 3. 問題回答

### 💡 問題一：
**測試一中，整理後的桌遊串列有 4 筆資料，為什麼桌遊費用應以 3 人計算？直接把字串拆成 list，和再轉成 set，各自保留了什麼、失去了什麼？**

1. **桌遊費用以 3 人計算的原因**：
   整理後的桌遊原始串列為 `['amy', 'ben', 'amy', 'cora']`。因為其中的 `'amy'` 重複出現了兩次。根據活動規則，同一個人重複報名只收一次費用，在實務中我們將其轉成集合去重後，桌遊實際參加者剩下 `{'amy', 'ben', 'cora'}`，共 3 人，因此桌遊費用應以 3 人計算。

2. **List 與 Set 的保留與失去**：
   - **字串拆成 List（串列）**：
     - **保留了**：報名者輸入的**原始順序**與**重複的報名次數**（也就是重現了當時誰先報名、誰重複報名了幾次）。
     - **失去了**：集合唯一性。我們無法直接、快速地做聯集、交集與差集的運算，也無法直接排除重覆項。
   - **再轉成 Set（集合）**：
     - **保留了**：**唯一且不重複的元素值**。這使我們能進行高效率的集合邏輯運算（例如誰兩場都到、誰只去特定一場）。
     - **失去了**：元素原有的**先後順序**（集合是無序的）以及**重複報名的次數資訊**（因為重複的資料會被自動合併成一個）。

### 💡 問題二：
**測試三中，兩場活動只有 3 位不同的人，為什麼是 6 人次、總應收仍是 600 元？請用集合關係與算式說明。**

1. **集合關係說明**：
   - 我們定義桌遊集合為 $A$，電影集合為 $B$。
   - 在測試三中，去重後的桌遊名單為 $A = \{\text{'amy'}, \text{'ben'}, \text{'cora'}\}$，而去重後的電影名單為 $B = \{\text{'amy'}, \text{'ben'}, \text{'cora'}\}$。
   - 兩場活動的**共同參加者**為交集：$A \cap B = \{\text{'amy'}, \text{'ben'}, \text{'cora'}\}$，人數為 3 人。
   - 兩場活動的**總不重複人數**為聯集：$A \cup B = \{\text{'amy'}, \text{'ben'}, \text{'cora'}\}$，人數也是 3 人。

2. **「人次」與「總應收」的算式說明**：
   - **報名人次**：指兩場活動「各自去重後的人數相加」。
     $$\text{報名人次} = |A| + |B| = 3 + 3 = 6\text{ 人次}$$
     雖然只有 3 個不同的人，但這 3 個人同時參加了桌遊與電影兩場活動。因此每個人佔了 2 個人次，總計為 6 人次。
   - **總應收費用**：由於每人次都需要消耗該場活動的場地與物資資源，兩場活動需分開獨立計費。
     $$\text{總應收} = (|A| \times 120) + (|B| \times 80) = (3 \times 120) + (3 \times 80) = 360 + 240 = 600\text{ 元}$$
     因此，即使總不重複人數只有 3 人，因每人都報名兩場，總應收費用依然是 600 元。
